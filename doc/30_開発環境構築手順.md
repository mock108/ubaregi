本書は、Android StudioやローカルAndroid SDKを使わず、GitHub Codespacesでウバレジを開発するための手順を定める。ローカルPCはブラウザ、Git、任意の軽量エディタだけで利用できればよい。

## 1. 開発環境の役割

| 場所 | 役割 |
| --- | --- |
| ローカルPC | ブラウザ、Git、軽量エディタ。Androidのビルドマシンにはしない |
| GitHub Codespaces | ソース修正、Gradle実行、Unit Test、Lint、APKビルド |
| GitHub Actions | CI、固定署名付きAPKの生成、Firebase App Distributionへの配布 |
| Android実機 | Firebase App DistributionからAPKを取得し、実使用・端末固有挙動を確認 |
| Firebase | Androidアプリの登録、App Distribution、テスター管理 |

GitHubリポジトリのルートは`mock108/ubaregi`、Gradleプロジェクトのルートは現状`pgm/ubaregi`とする。Codespacesのワークスペースはリポジトリルートで開き、Gradleコマンドは`pgm/ubaregi`で実行する。

次のソフトウェアはローカルPCに必須としない。

- Android Studio
- Android SDK
- Android Emulator
- JDK
- Gradle

端末の特殊な調査が必要な場合に限り、`adb`を含むPlatform Toolsを例外的に使用してよい。ただし、通常のビルド・配布・インストール経路には含めない。

## 2. Codespacesに固定する構成

`.devcontainer`をリポジトリルートに配置し、Codespacesを作り直しても同じ開発環境になるようにする。

| 項目 | 採用値・方針 |
| --- | --- |
| JDK | 17。Java / Kotlinの出力先も17に統一 |
| Android SDK | Android 17 / API 37 |
| Android command line tools | `.devcontainer`で導入。GUIのSDK Managerは使わない |
| SDK Build Tools | AGPの対応する安定版。現初期値は36.0.0を候補とし、初回ビルドで確定 |
| AGP | 9.3.2 |
| Gradle | 9.5.0。リポジトリ同梱のGradle Wrapperから実行 |
| 言語・UI | Kotlin、Jetpack Compose、Material 3 |
| DB | Room、KSPでコード生成 |
| ビルド記述 | Gradle Kotlin DSL、依存バージョンは`libs.versions.toml`に固定 |

Android Studioはこの構成の前提にしない。ツールの互換性を確認する場合も、実際にビルドを行うCodespacesとGitHub Actionsの環境を正とする。`+`や動的バージョンは使わない。

## 3. Firebaseを先に準備する

Codespacesを作る前に、Firebase側の配布先を用意する。プロジェクトIDやApp IDは実際に作成した値を記録し、例の値をそのまま使用しない。

1. `mock108/ubaregi`用のFirebase Projectを1つ作成する。例として`ubaregi-personal`のようなProject IDを候補にする。
2. FirebaseへAndroid Appを登録する。個人用配布APKの`applicationId`は`io.github.mock108.ubaregi.debug`とする。
3. Firebase App Distributionを有効にし、自分のGoogleアカウントをテスターとして登録する。
4. FirebaseのProject ID、Android App ID、テスターのメールアドレスを、[CI/CD設計書](35_CI-CD設計書.md)の対応する設定欄へ記録する。
5. GitHub ActionsからFirebaseへ接続する認証を設定する。初回はGitHub SecretsにService Account JSONを保存する方式を使い、長期運用ではOIDC / Workload Identity Federationへ移行する。

初期版の業務機能はオフラインで動かすため、Firebase Android SDKや`google-services.json`をアプリへ組み込むことを必須にしない。Crashlytics等を後から導入する場合だけ、アプリのデータ取扱いと設定を見直したうえで追加する。Service Account JSON、`google-services.json`、署名鍵は公開リポジトリへcommitしない。

## 4. Codespacesの作成

1. GitHubで`mock108/ubaregi`を開く。
2. **Code → Codespaces → Create codespace on main**を選ぶ。
3. `.devcontainer`が選択され、JDK・Android command line tools・API 37が利用できることを確認する。
4. リポジトリルートからGradleプロジェクトへ移動する。

```bash
cd pgm/ubaregi
java -version
./gradlew --version
```

`java -version`はJDK 17、Gradle Wrapperは9.5.0を示すことを初期確認とする。

## 5. Codespacesでの基本確認

アプリ実装後、次のコマンドをCodespacesで実行する。

```bash
cd pgm/ubaregi
./gradlew testDebugUnitTest lintDebug assembleDebug
```

上記が成功すれば、少なくともコンパイル、Unit Test、Lint、debug APK生成が可能である。生成物は次の場所に出る。

```text
pgm/ubaregi/app/build/outputs/apk/debug/
```

Instrumentation TestやエミュレータをCodespacesで常時動かすことは初期要件にしない。必要になった場合はGitHub Actionsの仮想環境またはFirebase Test Labを別途検討する。

## 6. Androidプロジェクト設定

| 設定 | 値・方針 |
| --- | --- |
| namespace | `io.github.mock108.ubaregi` |
| 公開版applicationId | `io.github.mock108.ubaregi` |
| 個人用applicationId | `io.github.mock108.ubaregi.debug`。debugビルドに`.debug`を付ける |
| minSdk / targetSdk / compileSdk | すべて37 |
| 初期versionName / versionCode | `0.1.0` / `1` |
| 表示名 | 公開版「ウバレジ」、個人用「ウバレジ（個人用）」 |
| 構成 | 単一`app`モジュール、Compose、ViewModel、Room |
| 課金 | 個人運用版はSDK・購入処理を組み込まず無効 |
| 保存 | アプリ専用内部領域のRoom DB。出力はStorage Access Framework |
| 権限 | 位置情報、連絡先、カメラ、電話、通知、広範なストレージ権限を要求しない |
| バックアップ | `allowBackup=false`とdata extraction rulesで業務DBを除外 |

個人用APKの通常配布は、debugの`applicationIdSuffix`を維持したまま、GitHub Actionsで固定の個人配布用署名鍵を使う。Codespacesで生成した一時的なdebug鍵のAPKを、Firebase配布済みアプリの更新版として使わない。

配布用署名、バージョン番号、Firebase App Distributionの設定は[CI/CD設計書](35_CI-CD設計書.md)を正とする。

## 7. リポジトリで管理するもの

Gitで管理するもの：

- Kotlinソース、設計書、README
- `.devcontainer`
- Gradle Wrapper、`gradle-wrapper.properties`
- `libs.versions.toml`など固定した依存バージョン
- RoomのスキーマJSON、架空データのテスト
- `.github/workflows/ci.yml`、`.github/workflows/distribute.yml`

Gitで管理しないもの：

- `local.properties`、IDE設定、`build`生成物
- Service Account JSON、署名鍵、パスワード、公開用設定の実体
- `google-services.json`など、実装上不要なFirebase設定ファイル
- 実際の配達記録、出力ファイル、端末ログ

`.gitignore`は補助にすぎないため、commit前に差分と変更ファイルを確認する。

## 8. 初期構築の完了条件

- Firebase Project、Android App、テスターが作成済み
- 新しいCodespaceでJDK 17、API 37、Gradle Wrapperが利用できる
- `testDebugUnitTest`、`lintDebug`、`assembleDebug`が成功する
- CI WorkflowがPRまたはpushで実行できる
- Distribution Workflowが`main`へのpushまたは手動実行で動く
- 固定署名APKがFirebase App Distributionへ届く
- Android実機へインストールし、同じアプリとして更新できる

これ以降のWorkflow、Secrets、IAM、配布、失敗時の対応は[CI/CD設計書](35_CI-CD設計書.md)と[公開・運用手順](40_公開・運用手順.md)に従う。
