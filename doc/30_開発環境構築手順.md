## 1. 開発環境

Windows上のAndroid Studioで開発し、Android 17の実機とエミュレーターで確認する。開発者登録やGoogle Playへの接続は個人用アプリの開発条件にしない。

| 項目 | 採用値 |
| --- | --- |
| Android Studio | Quail 3 / 2026.1.3 Patch 1 |
| Android Gradle Plugin（AGP） | 9.3.2 |
| Gradle | 9.5.0。リポジトリに同梱するGradle Wrapperから実行 |
| Gradle実行用JDK | 17。Java / Kotlinの出力先も17に統一 |
| Android SDK | Android 17 / API 37 |
| SDK Build Tools | AGP既定の36.0.0。通常はbuildToolsVersionを明示しない |
| 言語・画面 | Kotlin、Jetpack Compose、Material 3 |
| DB | Room 2.8.4、KSPでコード生成 |
| ビルド記述 | Kotlin DSL、バージョン管理はlibs.versions.tomlに集約 |

最新の開発ツールを追い続けず、上記の安定版の組合せを開始点とする。AGP 9.3の公式互換表はAPI 37・Gradle 9.5.0・JDK 17を示しており、9.3.2には修正が含まれる。[AGP公式情報](https://developer.android.com/build/releases/agp-9-3-0-release-notes) / [Android Studio公式情報](https://developer.android.com/studio/releases/past-releases/as-quail-3-release-notes)

AGP 9の組込みKotlinを使い、`org.jetbrains.kotlin.android`を重ねて適用しない。Compose Compilerプラグインと、採用する場合のSerializationプラグインは、解決されたKotlinのバージョンに揃える。RoomにはKAPTではなくKSPを使う。[組込みKotlin](https://developer.android.com/build/migrate-to-built-in-kotlin) / [Compose Compiler](https://developer.android.com/jetpack/androidx/releases/compose-kotlin) / [Room](https://developer.android.com/jetpack/androidx/releases/room)

Compose BOM、Lifecycle、KSP等の依存バージョンは、上記環境でビルドできる安定版を選定し、具体的な値をバージョンカタログに固定する。`+`や動的バージョンは使わない。初回ビルドで解決結果を確認する。

## 2. 環境導入時の手順

1. Android Studioを導入し、GitHubリポジトリの作業コピーを開く。
2. SDK ManagerでAndroid SDK Platform 37、Platform Tools、Build Tools 36.0.0、Android Emulatorを導入する。
3. Gradle実行用にJDK 17を指定する。Android Studio自身の実行用Javaとは区別する。
4. Device ManagerでAPI 37の安定版イメージを使う端末を作成する。課金を使わない個人用の確認ではPlay Store付きイメージは必須にしない。
5. Android 17の実機で開発者向けオプションとUSBデバッグを有効にし、本人の開発PCだけを許可する。

SDKの所在は各PCの`local.properties`に記録し、Gitへ登録しない。Android StudioやJDKが既にある場合は版と設定を確認して利用する。SDK・ライブラリの取得は開発作業の通信であり、インストール後のアプリのオフライン要件とは別である。

## 3. アプリ作成時の設定

`app`やGradle Wrapperは、次の値を使って作成する。単一の`app`モジュールと標準の`debug` / `release`だけを使用する。

| 設定 | 値・設定先 |
| --- | --- |
| namespace / 公開版applicationId | `io.github.mock108.ubaregi`、`app/build.gradle.kts` |
| debugのapplicationIdSuffix | `.debug`。個人用IDは`io.github.mock108.ubaregi.debug` |
| 表示名 | releaseは「ウバレジ」、debugは「ウバレジ（個人用）」 |
| versionName / versionCode | `0.1.0` / `1`。以後、配布更新ごとにcodeを増やす |
| minSdk / targetSdk / compileSdk | すべて37。maxSdkVersionは指定しない |
| 開発者名 | `Mockup`。アプリ情報の固定表示に使用 |
| 言語 / 金額 / 日時表示 | 日本語 / JPY整数 / Asia/Tokyo。保存時刻はUTC |
| 個人用の課金 | `BILLING_ENABLED = false`。購入ボタン・確認ボタン・課金SDK・購入用DBを設けない |
| 画面 | 4画面。Material 3標準部品、青系の単色アクセント、端末設定に従うライト / ダーク表示 |
| 保存 | アプリ内部のRoom DB。詳細設計書の形式を使用 |
| 外部保存 | OSの文書作成UI。広範なストレージ権限を要求しない |
| 個人用の権限 | インターネット、位置情報、連絡先、カメラ等を要求しない。問い合わせは外部ブラウザーに渡す |
| バックアップ | `allowBackup=false`に加え、クラウドバックアップ・端末間転送から内部データを除外するルールを設定 |

個人用の署名にはAndroid Studioが自動作成するデバッグ鍵を使う。公開用の鍵は公開準備時に生成する。通常更新でデータを保持するため、個人用を使っている間は同じアプリIDとデバッグ鍵を維持する。[Androidの署名方式](https://developer.android.com/studio/publish/app-signing)

公開用の追加設定は[release.properties.example](../release.properties.example)に項目だけ用意する。個人用のビルド・起動ではこの設定ファイルを要求せず、公開準備時にビルド処理へ組み込む。

## 4. 実装の順序

1. 4画面の遷移とアプリ情報、ローカルの説明表示を作る。
2. Roomと現金計算を実装し、開始・受渡し記録・補充・取出し・締めを通す。
3. 履歴の編集・取消・全クリア、再起動時の保持、二重保存防止を実装する。
4. 詳細設計書の独自CSV / JSON出力を実装する。
5. 実機で入力のしやすさ、文字拡大、機内モード、バックアップ除外を確認する。

ログイン、独自サーバー、広告、解析、DIフレームワーク、複数モジュール、外部会計APIは追加しない。画面はCompose、状態はViewModel、業務データはRoomという構成に留める。購入処理の空実装やSDKは追加しない。

DBの版は1から開始する。RoomのスキーマJSONはGitに登録し、以後の更新では移行処理を作る。移行失敗時にDBを自動削除する設定は使わない。実際の金額や購入情報をログに出力しない。

## 5. プロジェクト作成後の確認

次のコマンドはアプリ本体とGradle Wrapperの作成後に、リポジトリ直下で実行する。

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
.\gradlew.bat connectedDebugAndroidTest
```

後者はエミュレーターまたはUSB接続した実機を必要とする。テスト対象は[詳細設計書の第9節](20_詳細設計書.md#9-実装時の受入確認)とし、計算・保存・重複防止に意味のあるテストを用意する。初期インストールはAndroid StudioのRunから行い、以後の個人用APKは`app/build/outputs/apk/debug/`で確認する。

必要な依存の取得後、アプリを機内モードで確認する。開発用の依存解決と、利用者の端末でのアプリ通信を取り違えない。インストール失敗時に、データを失うアンインストールを最初の対処にしない。

## 6. リポジトリで管理するもの

ソース、設計書、Gradle Wrapper、固定した依存バージョン、Roomスキーマ、架空データのテストを管理する。`.editorconfig`と`.gitattributes`で文字コード・改行を揃える。

SDKパス、IDE設定、ビルド成果物、署名鍵、公開設定の実体、実際の配達記録は`.gitignore`の対象にする。手元の出力はリポジトリ外、または無視対象の`private/`・`exports/`に保管する。公開前に差分を確認し、秘密を含むファイルを強制追加しない。

環境値は本書を基準とする。アプリのビルド・端末確認は、プロジェクト作成後に本書の手順で行い、[公開・運用手順](40_公開・運用手順.md)の個人運用開始条件を満たしてから使用する。
